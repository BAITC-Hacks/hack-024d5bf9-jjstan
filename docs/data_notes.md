# Адаптеры данных StockPilot — Нурасыл

```python
from data_loader import load_data
dataset = load_data(["/path/to/Systeme electric.zip", "/path/to/IEK.zip"])
```

Python 3.10+, pandas, numpy, openpyxl; тесты: `python -m pytest tests/test_data.py -q`.
Исходники остаются локально. ZIP читается в памяти без распаковки; можно передать XLSX
с исходными именами и папками поставщиков. Все 8 таблиц контракта возвращаются всегда.
Синтетический сквозной пример находится в `tests/test_data.py`.

## Для интеграции

- **Расхождение контракта:** прямое задание Нурасыла задаёт `*all*`, TEAM_PLAN.md — `__all__`.
  Loader следует прямому заданию: `data_loader.ALL == "*all*"`. Координатору нужно
  согласовать маркер с engine; обязательные колонки не изменены.
- Сначала подключайте Systeme Electric. Дата снимка берётся из имени файла транзита.
  `is_current=True` означает актуальный снимок **на указанную as_of**, а не на день запуска.
  Engine должен отдельно проверять возраст снимка относительно settings.as_of.
- `quality_report.severity` содержит `info`, `warning`, `error`; issue — стабильный код.
- `monthly_sales` и `transactions` нельзя складывать. Для общего месячного прогноза
  основной источник — отдельный месячный отчёт. Динамика нужна для детализации/аномалий.
- Сентябрь 2026 неполный. При известной дате отчёта полными считаются только закончившиеся
  месяцы; иначе последний представленный месяц консервативно неполный.

## Правила источников

- Строковый код 1С сохраняет нули, подчёркивания и кириллицу. Числовые коды с Excel-форматом
  `00000` восстанавливаются по этому формату; без него потерянные нули не угадываются.
- Колонки/строки итогов исключаются. Пустые месячные клетки остаются NaN, а не нулём.
- В этих выгрузках расходная накладная сохраняет исходный знак: `quantity=raw_quantity`.
  Отрицательная накладная — возврат/сторно, положительная — продажа. Нельзя разворачивать
  всю таблицу по нескольким отрицательным строкам. Явный возврат от покупателя получает
  отрицательный знак. Неизвестный документ даёт NaN, raw_quantity
  сохраняется. Суммы сверяются с месячным отчётом по совпадающим SKU и месяцам.
- Свободный остаток Systeme Electric берётся напрямую; резерв повторно не вычитается,
  складские составляющие к общей величине не прибавляются. Общий снимок помечен `*all*`.
  Точное соответствие охвата месячной истории и снимка требует подтверждения.
- Исторический IEK — начало месяца: as_of=первое число, is_current=False.
  Исторический Systeme Electric не сообщает день снимка: as_of=NaT, report_month сохранён.
  Ни один исторический отчёт не доказывает свободный остаток после резерва:
  исходное число хранится в `stock_quantity`, `free_stock=NaN`.
- IEK ожидаемые даты — «поступление до» в заголовке, date_basis=arrival_deadline.
  У Systeme Electric 24.09 дополнено годом из имени файла. Это дата заголовка,
  date_basis=header_date_unconfirmed; её смысл как ETA нужно подтвердить.
  Неизвестные склады транзита остаются null. Пустая клетка транзита не доказывает нулевое поступление.
- Бухты/метры: никакого умножения на 305 по названию. При явном предупреждении источника
  `requires_unit_conversion=True`, quantity=NaN, raw_quantity сохранено, ограничения MOQ
  не применимы до подтверждения единиц.
- Systeme MOQ «Кратность» → pack_multiple; IEK «Мин. разр. к отгр.» → min_order_qty.
  Второе ограничение остаётся NaN. Единицы ограничений в MOQ отдельно не указаны.
- Сезонность берётся из готовой колонки «СЕЗОННОСТЬ» отдельного файла с category=`*all*`.
  Встроенные копии листов игнорируются. Профиль учитывает неполный 2026; мера продаж
  и применимость к штукам/метрам не подтверждены. Loader не пересчитывает прогноз.
- Категория 2026 сохраняется строкой без присвоения бизнес-смысла. Кэф. Роста и Кэф. Сез-ти
  сохраняются как growth_coefficient_raw / seasonality_coefficient_raw: это не подтверждённые
  множители прогноза; например, рост может быть отрицательной долей изменения.

## Отсутствует

Подтверждённая ежедневная stockout-история, customer_id, полный справочник сроков поставки,
отдельная BOM, актуальный остаток IEK. Stockouts возвращается пустым; customer_id=null.
Отсутствие движения не превращается в stockout. Номер накладной не является клиентом.
Неизвестные единицы, конфликты справочников и SKU только одного источника отражаются
в quality_report. Рекомендации при недостатке обязательных данных должен блокировать engine.
