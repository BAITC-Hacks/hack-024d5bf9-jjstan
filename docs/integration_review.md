## Что согласовать владельцам модулей

1. **Нурасыл + партнёр:** расхождения месячных продаж и динамики, неизвестные единицы и складской охват должны быть подтверждены. Ошибки нельзя просто понизить ради численного результата.
2. **Нурасыл + партнёр:** нужны актуальные свободные остатки IEK, подтверждённые единицы и условия MOQ. Пропуск второго ограничения не означает автоматически 0 или 1.
3. **Гапар:** тренд, аномалии и восстановление stockout остаются задачами алгоритма. UI их не имитирует.

В `0929436` Гапар уже исправил распознавание `*all*`/`__all__` и исключение исторических остатков до проверки складов. Новые настройки склада и отсутствующих MOQ доступны в раскрывающемся блоке UI: по умолчанию не заданы, требуют явного подтверждения пользователем. Они не отменяют ошибки качества; при проверке реальных архивов эти неподтверждённые значения не задавались. Основная причина в таблице выше — первая блокировка, после её устранения могут обнаружиться другие.

## Наша часть

Фронтенд, хранение черновика, явное утверждение, CSV-экспорт и диагностика реализованы отдельно. Нельзя утверждать неизвестное количество даже после ручной правки. Редактирование сохраняется по ключу товара; фильтр не меняет состав заказа незаметно. Любые изменения входов/количеств требуют нового утверждения.

Проверки и ограничения приведены для интеграции. Они не означают полного выполнения всех требований кейса текущими данными и базовым engine.
