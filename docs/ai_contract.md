# Предложение контракта AI v1 — Рамазан → Гапар

23.09.2026. Контракт нашей границы; подтверждение Гапара ещё не получено. Engine и loader не требуют изменений. Рамазан отдельно разрешил публикацию текущей сборки в feat/ui.

```python
explain_context(context: dict, *, question: str | None = None) -> dict
```

Контекст v1: `schema_version="1"`, `calculation_id`, `supplier`, `sku`, `as_of`, `source_mode`, `data_quality`, `facts`, `issues`.

`facts`: `forecast_qty`, `safety_stock`, `free_stock`, `incoming_in_horizon`, `raw_order_qty`, `recommended_qty`, `stock_as_of`, `unit`. Значения копируются из orders; NaN/NaT/Infinity преобразуются в JSON null. Новая арифметика и suggested/approved_qty не передаются.

`issues`: до 24 записей `{evidence_id, code, severity}` выбранного SKU, включая общие проблемы поставщика. Строки источников классифицируются локально; пути, имена файлов, имена товаров, клиенты и документы не передаются. Неизвестный код остаётся `unclassified_issue`, полный исходный текст доступен локально в UI. ID фактов: `fact:<field>`, ID статуса: `quality`, ID проблем: `issue:<digest>`. SKU — обезличенный корреляционный ID в сетевой сводке; исходный SKU остаётся в локальном контексте и ключе кэша.

Ответ всегда содержит ровно `status` (`ok`, `unavailable`, `invalid`), `summary` (строка), `evidence_ids` (список строк), `questions_to_manager` (список строк), `provider` (`openai`), `model` (строка). `question`: null, «Объяснить простыми словами» или «Что нужно уточнить»; свободный чат пока не включён.

Модель выбирает и упорядочивает только доступные проверенные тезисы и вопросы через строгую JSON Schema. Произвольный сгенерированный текст не попадает в интерфейс. Локальный renderer связывает тезисы с evidence и исходными facts. Это ограниченный AI-слой: модель определяет фокус и порядок, а формулировки/числа проходят детерминированную проверку. Для insufficient обязательны блокировка и вопросы, тезис с рекомендуемым количеством недоступен. Неизвестные ID, лишние поля, неверный статус/структура или неподтверждённые тезисы дают `invalid`; UI сохраняет обычное объяснение.

Сеть: официальный OpenAI SDK, Responses API, `text.format=json_schema`, strict, `store=False`, без tools. `OPENAI_API_KEY` и `OPENAI_MODEL` читаются из локального env или Streamlit secrets. Перед запросом проверяется доступ к настроенной модели через models.retrieve; совместимость Responses/схемы подтверждается только успешным ответом. Модель не подменяется автоматически.

Запрос только по кнопке, один активный вызов, общий таймаут около 15 секунд, не больше одного повтора временной ошибки; контекст ограничен 20 КБ, ответ 4 КБ/800 токенами. Никаких сетевых вызовов в unit-тестах.

Кэш только в сессии: calculation_id + supplier + sku + question + provider + model + prompt_version + digest контекста. Смена расчётных входов (включая выбор поставщика XLSX) очищает пояснения. Смена модели очищает AI-кэш, но не расчёт/утверждение. Чтение AI не меняет quantities или approval.

Engine Гапара cc15fe0 подключён: UI использует ENGINE_CAPABILITIES, настоящие флаги и таблицу anomalies. Ошибки сверки вне выбранного периода остаются видимыми; отдельный тезис mismatch_outside_period поясняет их неприменимость к текущему периоду. AI не определяет допустимость заказа: это результат engine и проверки утверждения.
